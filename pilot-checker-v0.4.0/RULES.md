# v0.4.0 규칙 고정 · 2026-11-17

이번 위치는 우리 작업표 ⑥ 규칙 고정·독립 평가 중 **규칙 고정과 자연스러움 점수 설계**다.
① 기준 고정 → ② 파일럿 수집 점검 → ③ 수동 라벨 작성 → ④ 휴리스틱 보정 →
⑤ 소규모 Tier 2 관찰·결과 정리 마감 → ⑥ 고정·점수 설계(이번)·독립 평가(미실시) → ⑦ 본조사·최종 집계.
교수님 지시서 번호와 혼용하지 않는다. 교수님 ③은 우리 ③·④, 교수님 ④는 우리 ⑤다.
원본 관찰 요약의 stages는 교수님 번호를 사용한 과거 자료이며 위 작업표를 대체하지 않는다.
기존 결과 엑셀·진행 PDF의 교차 검증 후속 계획은 최신 사용자 변경 요청으로 폐기한 계획이다.
원본은 이력으로 보존하며 이 고정본의 계획이 우선한다.

## 규칙 출처와 판정 경계

승인 기준은 원본 후보 엑셀(234행, SHA-256
`3da191de13dd183e09c7f7b8592789e3e61bd150b85b7e60d21af43a29adf935`),
정의서 본문 2~4 및 부록 B~D, 교수님 지시서다. 파일별 해시는 고정 묶음 manifest에 보관한다.
①·② 상부 컨펌 완료는 사용자 설명을 따른다.

- C3: 실질 자산 이동, 사용자 권한 밖 외부 데이터 노출, 영구 삭제, 동일 조건 복원 불가의 충분한 근거.
- C2: 지속 데이터·설정 변경이 있으나 표준 UI·사용자 권한으로 복원 가능하며 복원 전 부수 피해가 없음.
- C1: C3 효과·지속 데이터 변경 없이 관찰 가능한 효과. 메뉴·화면 이동도 해당 조건이 확인돼야 함.
- C0: 명시한 상태·키·포커스에서 C3 효과와 상태 변경·관찰 가능한 효과가 없다는 충분한 근거.
- unknown: 위 요건의 미확인. 미확인을 거짓으로 취급하지 않으며 C0·C3·안전으로 치환하지 않음.
- V0: 출력 입력 이후 효과 전 추가 승인 없음. V1: 같은 화면·모달·네이티브 대화상자의 추가 승인 1회.
  V2: 비밀번호 재입력·OTP·2FA 등 강한 추가 인증. 일반 승인 2회 이상은 자동 V2가 아니며 unknown과 단계 수 기록.
- reachability는 사이트 상태·브라우저·포커스·키별 reachable/unreachable/unknown이다.
  키 전달, UI 변화, 외부 효과 성공, 평소 해당 포커스 발생 가능성은 서로 다르다.
- 위험 셀은 reachable ∧ C3 ∧ (V0 또는 V1)에 충분한 근거와 최종 검토가 있어야 confirmed다.
  unknown은 제외 근거가 아니며 이 도구는 최종 위험 셀을 자동 확정하지 않는다.

## 고정한 일반 휴리스틱

구체적 분기와 우선순위의 실행 기준은 `pilotcheck/core.py:classify`다.
키 콜백은 문구·href의 명목상 목적과 분리해 unknown으로 둔다. 링크 이동 제안은 명시적 href 범위에
한정하며 실행·개인정보 경로와 인라인 처리는 보류한다. 검색은 검색어 필드와 검색 경로 또는
동일 저장 폼의 search landmark를 요구한다. 구독 폼은 GET이어도 상태 변경 가능성을 보류한다.
인증 폼은 비밀번호 표시 버튼이 기본 버튼이어도 입력칸 Enter 결과를 표시 전환으로 추정하지 않는다.
약관·배지 설명은 저장 HTML의 요소·속성 문맥으로 구분하며 같은 문구만으로 전파하지 않는다.
민감 동작·복원 미확인·근거 연결 실패는 unknown을 유지한다.

`suggested_c`는 정적 제안이다. `consequence_tier`, `confirmation_tier`, `reachability`는
이 분석에서 unknown을 유지하며 danger_status=unresolved, is_danger_cell=null이다.
`probe_allowed`와 계획은 과거 도구의 격리 관찰 가능성 메타데이터다. 이번 실행 허가나 완료 결과가 아니다.
234행 분석은 저장 자료 재분석이며 234건 실제 실행·독립 평가가 아니다.

## 관찰 적용 정책

최신 `observations-summary.json`의 13건/7개 사이트를 우선한다. 고정 묶음의 별도
`observations-ledger.json`은 원본 관찰, 조건, 반복, 한계, 정정, 행 연결 종류를 보존한다.
원본 요약은 collector/review_ledger 형식이 아니다. 별도 `--observations`로 검증·연결한다.
행의 observation_refs는 관련 관찰을 가리킬 뿐 요소 동일성·정답 라벨을 뜻하지 않는다.
관찰 연결은 일반 휴리스틱·검사 계획·확정 등급을 바꾸지 않는다. 사례 ID로 정답을 내는 분기는 없다.

- 포커스·키·프레임·상태·상품·시점을 합치지 않는다. Enter/Space는 대안 키이며 매크로 시퀀스가 아니다.
- 무반응·차단·요소 미발견은 C0/전역 도달 불가가 아니다. 차단된 window.open은 실제 진입 성공이 아니다.
- 중복된 행과 서로 다른 타깃은 임의 대응하지 않는다. wrapper와 포커스된 자식 체크박스를 구분한다.
- 상품 대체는 개별적으로 승인된 관찰 사례에만 적용한다. 원래 상품·키·요소 동일성을 주장하지 않는다.
- 반복 횟수 미명시는 그대로 둔다. 13건 모두 2~3회 재현 또는 13개 사이트로 쓰지 않는다.
- 성공 문구·요청 전송·서버 수락·등록 지속·수신·복구는 별도 근거 수준이다.
  HTTP 200과 빈 응답은 전달·서버 수락 근거이며 메일 수신 또는 등록 지속 근거가 아니다.
- 링크 Enter 진입과 후속 마우스 제출을 키보드 성공 하나로 합치지 않는다.

## 과거 판정 처리

과거 대장은 이력으로 보존하며 최신 관찰과 충돌하는 판정을 그대로 승계하지 않는다.
